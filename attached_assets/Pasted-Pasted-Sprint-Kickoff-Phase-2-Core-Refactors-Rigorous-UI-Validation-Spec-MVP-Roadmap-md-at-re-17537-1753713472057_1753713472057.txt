---

## B. Explicit UI Validation

Once the above is merged, **do not assume** things render correctly—**verify them**:

1. **Header Checks**  
   - **Logo**: Must appear on every page (Home, Feed, Detail, Canvas).  
     - Screenshot or DOM query for `<img src="/logo.svg">` or fallback text “Circles”.  
   - **Back Button**: Must exist on every non-root page.  
     - Verify with `aria-label="Back"` and click → navigates back.  
   - **Page Title**: Correct text rendered and centered.

2. **Safe-Area & FAB**  
   - On **iOS simulator** or dev device: FAB and bottom nav must respect safe-area inset (`pb-safe`).  
   - Touch zones ≥44×44 px (use overlay grid to confirm).

3. **Skeleton & Empty States**  
   - Simulate slow network (network throttling): skeleton loaders appear immediately.  
   - Navigate to empty resource pages: verify `EmptyState` component text and CTA.

4. **Error & Offline Banners**  
   - Inject network error (mock fetch failure): inline error message shows and “Try Again” works.  
   - Toggle offline mode in Chrome DevTools: offline banner appears.

5. **Accessibility Audits**  
   - Run `axe-core` in Storybook: zero violations in the updated components.  
   - Keyboard-only navigation: Tab through header, buttons, modals, confirm visible focus-rings.

6. **End-to-End Smoke Test**  
   - Deploy to staging.  
   - Manually click through:  
     - Open Feed → CreateCanvas → List Starter → Publish → verify toast.  
     - Open Restaurant Detail → Rate → verify modal uses new ModalWrapper.  
   - Log any console warnings/errors.

---

- **CHANGELOG.md**: add “Phase 2 Refactors & UI Validation” entry.  

Thank you—this rigorous approach ensures we ship not just code, but a truly polished, error-free, user-validated MVP.
