Systemic Fix — Restaurant Identity, Ratings, Circle Score (Final)
Mode: Implementation (safe, surgical).
Non-Goals: No visual facelift. No net-new features beyond what’s required to fix integrity, consistency, and performance.
Guardrails: TypeScript strict, do not alter auth, do not change global layout/header, do not change unrelated features.

Objectives
Eliminate cross-restaurant rating contamination (e.g., Badiali vs Villa di Roma).

Provide a canonical restaurant identity path: all reads/writes use restaurantId (not raw placeId) after one-time resolution.

Implement the missing Circle Score endpoint and make both widgets consume the same data/key.

Filter test data (e.g., is_test = TRUE) out of all production reads.

Unify fetches (one hook) + remove duplicate rating renders to cut calls and stop race conditions.

Wire cache/invalidation so rating writes refresh Circle Score consistently.

Produce validation docs proving the above across multiple restaurants (incl. Badiali).

1) Canonical Identity Resolver (server)
Files:

server/services/restaurantIdentity.ts (new)

server/routes/restaurants.ts (wire in)

Implement:

resolveRestaurantId(input: { restaurantId?: number; placeId?: string }):

If restaurantId given → validate exists, return it.

Else if placeId given → lookup in restaurants.google_place_id.

If not found, upsert a restaurant row with that placeId + basic fields (name optional until Places hydrate).

Return the newly created/located restaurantId.

Log IDENTITY_RESOLVE with { restaurantId, placeId }.

All rating/circle score endpoints must call this first and then operate strictly by restaurantId.

4) Ratings API — identity & fallback hardening (server)
File: server/routes/ratings.ts

On reads and writes:

Call resolveRestaurantId({ restaurantId: req.params.id, placeId: req.query.placeId }).

Always query by the resolved restaurantId.

If features.RATING_FALLBACK_DISABLED === true, never fetch/show ratings by placeId directly once an restaurantId is known.

On writes:

Normalize payload to persist restaurant_id and never persist ratings that only have placeId.

If you encounter rows missing restaurant_id, ignore them in reads, and add a one-time log line RATINGS_ROW_QUARANTINED.
