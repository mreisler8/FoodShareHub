React Hooks Violation Audit Report
RestaurantDetailPage.tsx Navigation Error Analysis

Critical Finding: Conditional Hook Enablement Pattern
Root Cause Identified
The error "Rendered more hooks than during the previous render" occurs due to a conditional hook enablement pattern in the RestaurantDetailPage component that violates React's rules of hooks.

Primary Violation: Lines 252-273
// PROBLEM: Conditional parameter creation
const restaurantParams = React.useMemo(() => {
  if (!googlePlaceId) {
    return null; // ❌ This causes hook enablement to change
  }
  return { googlePlaceId, name };
}, [dependencies]);
// PROBLEM: Hook called with changing enablement
const { userRating, circleScore, ... } = useStandardizedRestaurantQueries(restaurantParams);

Recommended Remediation Strategy
Phase 1: Immediate Stabilization
Always Enable Hooks: Remove conditional enablement and handle loading states internally
Stable Parameter Structure: Provide consistent parameters structure, never null/undefined
Guard Clause Relocation: Move validation logic inside query functions, not enablement conditions
Phase 2: Architecture Improvement
Parameter Resolution Refactor: Stabilize restaurant identification logic before hook calls
Custom Hook Enhancement: Make useStandardizedRestaurantQueries more resilient to parameter changes
Query Key Standardization: Ensure consistent query keys regardless of parameter source
Phase 3: Navigation Flow Optimization
Route Parameter Normalization: Standardize how restaurant IDs are passed through navigation
State Persistence: Implement proper state management for navigation transitions

This audit reveals a clear violation of React's hooks rules causing navigation failures. The conditional enablement pattern must be refactored to ensure hooks are always called in the same order with stable parameters.
