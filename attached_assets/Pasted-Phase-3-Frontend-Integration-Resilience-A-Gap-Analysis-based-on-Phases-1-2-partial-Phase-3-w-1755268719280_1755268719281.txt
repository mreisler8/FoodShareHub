Phase 3 — Frontend Integration & Resilience
A) Gap Analysis (based on Phases 1–2 + partial Phase 3 work)

What’s confirmed done

Single source of truth for restaurant data via useStandardizedRestaurantQueries.

Circle Score unified to the same hook & 10-point scale everywhere.

Mock content removed (lists/posts now real endpoints).

Redundant calls reduced ~40%; cache keys standardized.

Component-level error boundaries introduced for some core widgets (rating & circle score).

What’s still missing / inconsistent

Error boundary coverage isn’t universal

Some async widgets (photos/gallery, related posts/lists tiles, map/location, similar restaurants) still rely on implicit try/catch and can trip the global boundary.

Loading state cohesion

Multiple spinners show at once; no skeletons for “above the fold” blocks → visible layout shift on slow networks.

Race conditions after mutations

Rating submit + list add/remove can “duel” invalidate different caches; occasionally surfaces stale score or duplicate fetches.

Telemetry/observability

Search/perf middleware exists server-side, but client lacks uniform widget-level timing & error instrumentation.

A11y parity across widgets

Modals fixed, but some buttons/cards/slider ARIA roles/labels are missing; keyboard traversal inconsistent.

Network resiliency glue

Not all queries use shared retry/backoff/cancellation. Some still default to react-query defaults (retry 3, no jitter), causing request thundering on flakey networks.

Empty states consistency

Lists/posts/ratings empty states vary by widget (copy, iconography, CTA alignment).

B) Phase 3 Implementation Plan (surgical, low risk)
1) Universal Error Boundaries & Fallbacks

Add a tiny wrapper: client/src/components/common/SectionBoundary.tsx

Props: title, fallback, onError?(err).

Usage: Wrap every async widget (Photos, Map, ListsMentionCard, PostsMentionCard, SimilarRestaurants).

Fallbacks live in client/src/components/common/fallbacks/*:

InlineError.tsx, SkeletonCard.tsx, EmptyState.tsx.

Success: No “global” error boundary shows during any single widget failure; page remains interactive.

2) Cohesive Loading (Skeleton-first)

Introduce shared skeletons:

RestaurantHeaderSkeleton, ScoreStripSkeleton, ActionBarSkeleton, TilesSkeleton.

Replace spinners in page-critical regions with skeletons; below-the-fold keeps small spinners to reduce DOM weight.

Gate by isFetching from the unified hook; avoid double spinners by coordinating child queries to the parent’s loading state.

Success: 0 layout shifts above the fold; only one visible loading pattern per area.

3) Post-mutation Consistency (Cache & Events)

Centralize invalidation: client/src/features/restaurant/cache/restaurantCache.ts

Helpers: invalidateRestaurant(restaurantId), invalidateScores(restaurantId), invalidateMentions(restaurantId).

Event bus (tiny): client/src/lib/events.ts

Emit rating:updated, list:changed. Widgets subscribe and reconcile their local state without re-fetch storms.

In rating & list mutations: call both invalidate* and emit the event.

Success: After rating or “add to list,” all widgets reflect new data within one render; no duplicate fetches.

4) Client Telemetry (Widget-level)

Utility: client/src/lib/telemetry.ts

trackTiming(name, ms, {restaurantId})

trackError(name, {message, code, restaurantId})

Wire into: data hooks (onSuccess/onError), SectionBoundary onError, and mutation onSettled.

Add a dev overlay gated by ?debug=1 to show timings per widget (non-blocking).

Success: We can see which widget is slow/failing without server logs; perf regressions become obvious.

5) A11y parity & keyboard support

Audit fixes:

All action buttons: aria-label, focus ring classes, role="button" if needed.

Rating slider: ensure role="slider" + aria-valuemin/max/now, arrow key handling already present.

Cards as links: ensure role="link" + Enter/Space triggers.

Run axe-core (or jest-axe) in a single accessibility test file for the restaurant page shell.

Success: No critical a11y violations in the restaurant page; keyboard-only flows pass.

6) Network resiliency & cancellation

Shared fetcher layer: client/src/lib/fetcher.ts

AbortController per request, auto-cancel on component unmount, jittered retry (50–150ms) with max 2 retries for idempotent GETs.

Ensure all data hooks use this fetcher (quick pass with code search).

Success: Fast tabbing/navigation doesn’t leave orphaned requests; fewer duplicate/mid-flight errors.

7) Empty states standardization

EmptyState.tsx patterns: icon + concise copy + primary CTA (e.g., “Be the first to rate”).

Ensure copy parity across lists/posts/ratings.

Success: Empty states feel intentional and consistent.
